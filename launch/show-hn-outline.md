## Verified fact bank

These are implementation facts, not evaluation outcomes:

- Scope is cloud and software-system architecture, not ERDs, sequence
  diagrams, UML, or general-purpose flowcharts.
- Invocation is explicit and manual.
- With permission, the workflow may inspect relevant repository files,
  Terraform, Kubernetes manifests, and Docker Compose as read-only evidence.
- Repository content is treated as untrusted data and is not executed.
- The agent asks only unresolved topology questions, then presents an
  evidence-linked Architecture Brief.
- No diagram files may be written before that specific brief is approved.
- A constrained JSON IR is validated before trusted Python is generated.
- The renderer uses `diagrams==0.25.1` and local Graphviz to produce SVG plus a
  render manifest; PNG is optional.
- Python and Graphviz are checked but never installed automatically.
- Missing exact provider icons use a visible Generic Blank fallback rather
  than a fuzzy substitution.
- Output bundles do not silently overwrite an existing diagram.
- The repository defines 12 fixed synthetic fixtures and a two-condition,
  24-run prelaunch protocol. That statement does not claim the runs are
  complete or that the skill wins.
- Three OSS case definitions are pinned by commit for later evaluation; their
  presence is not evidence that those repositories were successfully tested.

## Body outline for the user

1. **Personal problem**
   - What repeatedly went wrong when architecture diagrams were drawn before
     unresolved decisions were surfaced?
   - Give one concrete, truthful example from development.
2. **Why existing interaction was insufficient**
   - Separate rendering quality from architecture-decision quality.
   - Explain why a polished diagram can still encode unsupported assumptions.
3. **What the project does**
   - Evidence map → decision interview → approved brief → constrained IR →
     generated bundle → real-image visual check.
4. **How it is constrained**
   - Manual invocation, read-only inspection, approval before writes, exact
     icon catalog, no automatic dependency installation, collision safety.
5. **What was evaluated**
   - State the fixed protocol and link raw reviewed records.
   - Include results only after the complete matrix passes the claim gate.
6. **What failed or remains limited**
   - Add at least one actual observed failure when records exist.
   - State runtime prerequisites, narrow diagram scope, and any unverified
     clients.
7. **How to try it**
   - Public install command, one copyable prompt, prerequisites, and expected
     output bundle.
8. **Question for HN**
   - Ask for feedback on one genuine design tradeoff rather than asking for
     stars.
